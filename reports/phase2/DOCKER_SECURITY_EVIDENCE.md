## 2. Remediation

### R1. Rotate the root password inside MongoDB (required before HTTPS exposure)

Prepared: `reports/evidence/phase2/docker-root-remediation.sh` (not run).
- It authenticates in-container with the stored value, read by mongosh JavaScript from the container's own environment.
- It sets `devroot` to 48 random bytes generated in-container and **discarded**.
- It then runs `docker-root-verify.sh`.
- No value appears on a command line, in output, or on disk.

**Effect:**
- The value in `docker inspect` becomes dead.
- The app user is unchanged, so the app, `seed` and `verify` keep working.
- Root is used only by `dev:db setup`. If it is ever needed again, `npm run dev:db -- reset --yes` rebuilds the test database (test data only).

**Done-criteria:**
- `docker-root-verify.sh` prints **NOT USABLE**;
- `npm run dev:db -- verify` still passes 13/13;
- the running-app isolation check still passes 8/8.

### R2. Restrict the secret files to the owner

- **Done** for `.env.isolated-test.session.local` (`ali` + SYSTEM only).
- `scripts/isolated-env.mjs` now applies the same restriction to `.env.isolated-test.local` the first time it runs after you create it. `--check` reports "owner-only".

**Recommended (your decision; content unchanged):** restrict `.env.local` the same way:

```
icacls .env.local /inheritance:r /grant:r "%USERDOMAIN%\%USERNAME%:(F)" "SYSTEM:(F)"
```

### R3. Optional hardening (your decision)

Re-create the container without `MONGO_INITDB_*` variables, reusing the same data volume, so even the dead value disappears from `docker inspect`. For future setups, pass the root password with `MONGO_INITDB_ROOT_PASSWORD_FILE` instead.
