# Environment setup

_Generated by `npm run docs:env` from `lib/ai/env-registry.ts` — the same registry `/test` uses to report set / missing / invalid. Edit the registry, not this file._

Put values in `.env.local` (development) or `.env.production.local` (server), restart the app, then open **/test** (admin login) to see what is connected. Values are never shown anywhere — only whether each one is set and looks valid.

**Legend** — *Required*: the site needs it. *Required for this feature*: that integration/agent does not work without it. *Optional*: has a safe default. **Agents**: chat = Agent 1, voice = Agent 2, growth = Agent 3, whatsapp = Agent 4, platform = the store itself. **Scope**: both / production / development.

## Setup order

1. **Platform**: MongoDB, AUTH_*, admin, SMTP — the store and owner alerts.
2. **Gemini**: GEMINI_API_KEY — all four agents switch from catalogue-only to Gemini replies (still checked against catalogue facts).
3. **Jobs**: CRON_SECRET, then schedule `POST /api/ai/jobs` every 15 minutes and `POST /api/ai/report/daily` daily with `Authorization: Bearer $CRON_SECRET`.
4. **Google**: create the service account, paste GOOGLE_SERVICE_ACCOUNT_JSON, grant GA4 Viewer and Search Console access, set GA4_PROPERTY_ID and SEARCH_CONSOLE_SITE_URL.
5. **WhatsApp**: Cloud API token + IDs, webhook verify token and app secret; coexistence per docs/phase2/WHATSAPP_COEXISTENCE_SETUP.md.
6. **Voice**: Exotel KYC + vSIP, then Vapi credential/number/assistant; press “Sync Vapi assistant” in Admin → Marina AI → Health.

🔒 = secret. Keep it only on the server; never in frontend code, chat or screenshots.
